# 浏览器跳转与媒体嗅探回归

## 本次修复

- 全屏、悬浮浏览器统一通过 WebView 的新窗口传输机制接收 `target="_blank"` 和用户点击触发的 `window.open()`，允许中间的 `about:blank` 页面，不根据点击图片推断目标，也不把新窗口初始化成首页。
- iframe 的导航交由其自身加载，避免跟踪清理、安全提示或外部应用处理把子框架提升为整页跳转。
- 自动弹窗和自动唤起外部应用会提示拦截；证书错误仅取消异常连接，不把主页面送回首页。取消风险提示保持当前页面，拒绝后再次访问仍需确认。
- 广告过滤只匹配主机名、只拦截子资源，避免正常 URL 的路径、参数中出现广告域名时被误拦。
- 仅删除明确的跟踪参数，保留 `from/source/ref/referrer` 等功能参数、原始编码、重复参数顺序和签名链接。清理后的目标仍经过风险检查。
- 媒体嗅探合并音视频元素、同源框架、资源时序、WebView 各框架请求及 MacCMS 公开播放器配置，识别 HLS、DASH、常见音视频格式及播放器 URL 参数。提供刷新按钮，便于播放后再次扫描。
- 忽略 `blob:`、`data:`、脚本及本地文件地址，不把分片或播放器 HTML 当作媒体直链。不会重放网络请求，也不会处理 DRM。跨域 DOM 无法直接读取时依靠实际媒体请求；没有文件后缀且没有媒体 Accept 类型的跨域请求仍可能无法识别。
- 安全规则移除了较新 Android 版本才提供的 `Set.of`，保持 Android 8.0 起的兼容性。不可控制的跨域播放器不再提示倍速设置成功。

## 自动回归

在仓库根目录执行（JDK 17 或更新版本、Node.js 18 或更新版本）：

```powershell
./tests/run-browser-tests.ps1 -JavaHome '你的 JDK 目录'
```

包含 34 项 Java 断言与 8 个 JavaScript 用例，覆盖 URL/主机判定、功能参数和签名保留、大小写请求头、嵌套媒体参数、编码播放器配置、跨域框架隔离、blob 播放器、动态刷新和数量上限。产物保存在忽略的 `build/browser-tests`。

Android 完整检查：

```powershell
./gradlew.bat :app:lintDebug :app:assembleDebug
```

## Android 设备验收

以下场景需分别在全屏与悬浮浏览器执行，不能用桌面 Chrome 的测试代替 WebView 验证：

1. 访问 `https://go.taolove.top/`，点击文字链接及图片链接，确认新标签页进入正确网站，原导航页保留。对需要确认的网站，取消后应保持原页面；再次访问仍有提示。
2. 用户点击触发的 `window.open(url)`、先 `window.open('about:blank')` 再设置 `location`、`target="_blank"` 的 POST 表单，均应保留浏览器原生导航行为。无用户手势的弹窗应被阻止。
3. 页面内 iframe 跳转到含 `source/ref/utm_source` 的播放器，确认主地址栏和主页面不变。
4. 子资源证书异常时确认有提示，主页面不会跳回首页；主页面证书异常仍不能加载。
5. 访问 `https://skr.skr2.cc:666/vodplay/286954-4-1/`，点“媒体”；应识别当前集播放器配置中的 `.m3u8` 地址。若页面延迟创建播放器，先播放再刷新。换集后不应混入上一集缓存。
6. 切换标签页，检查媒体缓存不互相混入；测试 HLS/blob、同源 iframe 与跨域 iframe 播放器，以及无法控制倍速时的提示。

示例视频页面的配置字段 `encrypt=2` 是播放器 URL 的 Base64/百分号编码，不是视频 DRM。页面及 CDN 地址可能随站点更新变化，测试应比较当前公开配置，而非固定某个临时视频 URL。
